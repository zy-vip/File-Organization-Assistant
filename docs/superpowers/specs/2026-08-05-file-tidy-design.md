# 文件整理助手（FileTidy）设计文档

- 日期：2026-08-05
- 状态：已确认
- 技术栈：C# / .NET 8 + WPF

## 1. 产品概述

一款 Windows 桌面文件自动整理工具。用户配置规则（按扩展名、文件名关键词、修改日期），将源文件夹中的文件自动移动到指定目标文件夹，整理前可预览，整理后可撤销。定位对标 macOS Hazel——Windows 上目前没有成熟同类产品。

### 核心价值

- 解决 Windows 用户桌面/下载文件夹杂乱的真实痛点
- 免费 + 付费解锁模式：MVP 免费功能完整可用，Pro 功能（正则条件、重命名模板、重复文件检测）后续版本通过付费解锁

### 产品形态

- 手动为主：用户点击"立即整理"触发
- 可选自动：开启托盘常驻后，监听文件夹变化自动整理（新文件到达延迟 3 秒，避免写入未完成）

## 2. 目标用户与场景

- 普通 Windows 用户：下载文件夹、桌面长期杂乱，希望一键分类
- 场景示例：Downloads 里的安装包自动进"安装包"，图片进"图片"，超过 30 天的文档进"归档"

## 3. 功能范围（MVP）

### 3.1 规则系统

每个规则 = **源文件夹 + 条件组 + 动作**

- **条件**（满足其一即触发，MVP 三类）：
  - 文件扩展名 ∈ 指定列表（如 .jpg .png .gif）
  - 文件名包含指定关键词
  - 最后修改日期距今 ≥ N 天
- **动作**（MVP 仅一种）：
  - 移动到目标文件夹
- 规则按顺序执行，先命中先处理
- **单轮不重复处理**：一个文件被某规则处理后，本批整理不再进入后续规则匹配
- 未被任何规则命中的文件留在原地，在预览中标出

**扫描行为**：
- 递归包含源文件夹下所有子目录
- 选项「排除目标文件夹树」默认开启：扫描时自动排除本规则目标文件夹（含其子路径），防止"整理进去又被整理出来"的循环
- 选项「包含子文件夹」默认开启；关闭后仅扫描源文件夹第一层
- 源文件夹与目标文件夹相同/重叠时，编辑时即时校验并警告

### 3.2 核心交互

1. 配置规则 → 实时保存到 `%AppData%\FileTidy\config.json`
2. **预览结果**：扫描源文件夹 → 规则匹配 → 表格显示"源文件 → 目标路径"，冲突/未命中文件标黄，不实际移动
3. **立即整理**：按预览执行，但执行前对每个文件做**再校验**（仍存在、仍匹配规则）；统计（成功 N / 跳过 M / 失败 K，失败原因列表）
4. **撤销上次整理**：每次整理生成**持久化操作日志**（含原路径↔新路径映射与时间戳，存盘），重启后仍可撤销；撤销完成即作废该日志，可对历史记录逐次回退（仅保留最近 10 份日志）
5. **可选自动整理**：托盘常驻 + 文件夹监听，自动跑规则，托盘通知结果

### 3.3 界面（简体中文）

主窗口三栏式：左侧规则列表，中间规则编辑器（源文件夹、三类条件、目标文件夹、冲突处理开关），底部操作按钮（立即整理/预览结果/撤销上次整理）+ 状态栏。托盘图标常驻（开启自动时）。

### 3.4 全局设置

- **开机自启**：可选（注册表 Run 键），托盘常驻类工具的标准能力
- 自动整理开关（默认关）
- 冲突自动追加序号开关（默认开）
- 操作日志保留份数（默认 10）

## 4. 架构

```
FileTidy（解决方案）
├── FileTidy.Core          // 领域核心（无 UI 依赖）
│   ├── RuleEngine         // 规则引擎：条件匹配 → 动作
│   ├── FileScanner        // 扫描源文件夹，收集候选文件
│   ├── Organizer          // 执行移动，处理冲突，记录操作日志
│   ├── OperationLog       // 操作日志：持久化存储/读取/作废
│   ├── PreviewService     // 预演：计算整理结果但不落地
│   ├── FolderWatcher      // FileSystemWatcher，可选自动整理
│   └── EngageQueue        // 整理互斥队列：手动/自动任务串行执行
├── FileTidy.App           // WPF 主程序
│   ├── MainWindow         // 主界面
│   ├── TrayIcon           // 系统托盘常驻
│   └── SettingsService    // 规则/配置持久化（JSON）
└── FileTidy.Tests         // xUnit 单元测试 + 集成测试
```

### 数据流

1. 用户配置规则 → SettingsService 写 JSON（实时保存）
2. 点击预览 → FileScanner 扫描源文件夹（递归、排除目标树）→ RuleEngine 匹配 → PreviewService 生成预览集合
3. 点击整理 → 任务进入 EngageQueue → Organizer 按预览执行（执行前再校验、处理冲突、写持久化操作日志）
4. 撤销 → OperationLog 读取最近一份日志 → Organizer 反向移动 → 成功后退栈作废该日志
5. 自动模式 → FolderWatcher 监听到变更 → 延迟 3 秒 → 任务进入 EngageQueue（与手动整理互斥串行）→ 走 2-3 流程 → 托盘通知

### 配置存储

`%AppData%\FileTidy\config.json`：规则列表 + 全局设置（自动整理开关等）。

## 5. 错误处理

| 场景 | 处理 |
|------|------|
| 目标文件夹不存在 | 首次执行自动创建；创建失败报错并跳过该规则 |
| 文件名冲突 | 自动追加序号（报告.pdf → 报告(1).pdf），可关闭 |
| 文件被占用/无权限 | 跳过该文件计入失败列表，不中断其余文件，结束时列出原因 |
| 跨卷移动（C→D） | File.Move 跨卷失败，改用 Copy+Delete 分步执行；中途失败删除已复制副本并计入失败列表 |
| 撤销时文件已缺失 | 跳过并提示，不报错中断 |
| 非法配置 | 编辑时即时校验提示（源文件夹不存在、条件为空、源=目标等），不写盘 |
| 源=目标/目标在源内部 | 编辑时警告；扫描时自动排除目标树，杜绝循环整理 |
| FileSystemWatcher 缓冲溢出 | 自动切换为整目录重新扫描 |
| 手动与自动整理并发 | EngageQueue 互斥串行，整理期间拒绝重复触发并提示 |
| 预览后文件已变化 | 执行前逐个再校验（存在性、规则匹配），失效文件跳过并计入跳过列表 |

## 6. 测试策略

| 层 | 覆盖点 |
|----|--------|
| 单元测试 | 条件匹配（扩展名/关键词/日期边界值）；冲突序号生成；规则优先级；单轮不重复处理；配置序列化往返；操作日志序列化往返 |
| 集成测试 | 临时目录造文件模拟：移动成功、冲突、被占用跳过、撤销还原；撤销日志跨"重启"（新实例读取旧日志）可用；目标树排除防循环；跨卷移动（两个不同临时盘符目录）；自动模式触发；EngageQueue 并发互斥 |
| 手动验收 | 真实下载/桌面目录演练，预览与实际执行一致 |

## 7. 免费/付费边界（MVP）

- **免费**：MVP 全部功能
- **Pro 占位**：界面预留 Pro 徽标位；正则条件、重命名模板、重复文件检测为后续付费项，MVP 不实现（仅在规则编辑器中预留扩展点）

## 10. 非目标（MVP 不做）

- 正则条件、重命名模板、重复文件检测（Pro 预留）
- 多文件夹联动（一个源按编排规则分发到多个目标的联动编排）
- 国际化（仅简体中文）
- 自动更新机制
- 开机自启以外的系统集成（右键菜单、文件关联等）
