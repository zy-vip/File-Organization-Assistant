# 文件整理助手（FileTidy）二期设计文档

- 日期：2026-08-06
- 状态：已确认
- 技术栈：C# / .NET 8 + WPF
- 一期已完成：规则整理（扩展名/关键词/日期）、预览、执行、撤销、自动监听、托盘、开机自启

## 1. 二期目标

在一期 MVP 之上，一次性交付三个相互关联的能力：

1. **正则表达式条件**（Pro）：用正则匹配完整文件名，替代基础关键词的弱匹配能力
2. **重命名模板**（Pro）：按模板重命名文件（内置变量 + 正则捕获组 + 批内序号），支持冲突兜底
3. **免费/付费（Pro）变现机制**：离线激活码 + 试用期（限天数 + 限次数）+ 激活码生成器，执行时拦截 Pro 功能

同时通过**动作抽象化重构**为后续「多目标联动编排」铺路，并为「重复文件检测」预留 Pro 门控扩展点（本期不实现其功能本身）。

### 核心价值

- 把一期"隐式移动动作"升级为显式 `RuleAction` 模型，重命名能力与付费墙有统一的载体
- 免费版可完整试用 Pro 功能，试用耗尽后执行时拦截引导购买，变现路径清晰

## 2. 目标用户与场景

- 下载了大量实验数据/项目文件、文件名带编号但无规律的开发者
- 场景示例：下载文件夹中的 `2026-Q1报告-final.pdf`、`IMG_20260101.jpg` 等，用正则提取编号、按月份重命名入库
- 愿意为自动化持续整理付费的 Pro 用户

## 3. 功能范围（二期）

### 3.1 动作模型抽象（重构）

通过多态序列化把"移动"动作化，为后续动作扩展铺路。

```
RuleAction（抽象基类，[JsonDerivedType] 多态序列化）
├── MoveAction               // 纯移动（免费）
└── MoveAndRenameAction      // 移动 + 重命名模板（Pro）
     └── Template: string    // 重命名模板
```

- `Rule` 新增 `Actions` 列表，**缺省为空 = 视为 MoveAction**（隐式缺省兼容旧配置，不写迁移代码）
- `TargetPath` 保留在 `Rule` 上（目标属于规则，动作只决定"做什么"），预览/执行统一从 `Rule.Actions[0]` 解释动作
- **单动作约束**：每个规则最多 1 个动作，编辑时限定，界面下拉选择
- `RuleAction` 携带 `RequiredFeature`（null = 免费）供门控检查
- `FileCondition` 同样增加虚属性 `RequiredFeature`（默认 null，免费）；`RegexCondition` 返回 `RegularExpression`。预览/执行时聚合规则中**所有条件与动作**的 `RequiredFeature`，任一被使用即为该规则所需功能

### 3.2 正则表达式条件（Pro）

```
RegexCondition : FileCondition
├── Pattern: string      // 正则，匹配完整文件名（含扩展名）
└── IgnoreCase: bool     // 默认 true
```

- 注册 `[JsonDerivedType(typeof(RegexCondition), "regex")]`（与现有 Extension/Keyword/Age 并列）
- 匹配目标为**完整文件名**（含扩展名），默认忽略大小写，提供「区分大小写」开关
- 编译失败的正则：编辑时即时校验提示，校验不过禁止保存
- 捕获组可被重命名模板引用（`{1}`、`{2}`…）
- **捕获组提取机制**：模板引擎需要正则的**匹配结果**而非布尔。`RegexCondition` 额外实现 `MatchResult? Match(FileEntry)`（返回命名编号捕获组值数组，未命中为 null）；模板渲染时从**该规则按列表顺序的第一个 RegexCondition** 提取捕获组；规则无正则条件而模板引用 `{1}` → 渲染失败标记「模板错误」

### 3.3 重命名模板（Pro）

模板渲染后得到目标文件名，相关动作是 `MoveAndRenameAction`（移动到 `Rule.TargetPath` + 重命名）。**模板输出即最终文件名，是否含扩展名由模板内容决定**（如只写 `{name}_{date:yyyyMMdd}` 则结果不带扩展名），系统不再自动补扩展名。

**变量语法**

| 变量 | 含义 | 示例 |
|------|------|------|
| `{original}` | 原始文件名（含扩展名） | `{original}_new` → `report.pdf_new` |
| `{name}` | 原始文件名（不含扩展名） | `{name}_v2` → `report_v2` |
| `{ext}` | 原始扩展名（含点，保留原样） | `图片{ext}` → `图片.jpg` |
| `{date:格式}` | 今天日期，格式用 .NET 日期格式串 | `{date:yyyyMMdd}` → `20260806` |
| `{n}` | 批内递增序号（1 基）：**该规则命中的文件集合内**按扫描顺序从 1 编号，每个规则独立重新起算 | `订单{n}` → `订单1`、`订单2`… |
| `{1}` `{2}`… | 该规则第一个正则条件的捕获组 1、2… | 正则 `(\d{4})-(\d{2})` → `{1}_{2}` |

> **捕获组索引语义（2026-08 确认）**：捕获组索引从 1 起；`{0}`（等价完整匹配）与负数在模板校验时拒绝。可选捕获组（如 `(IMG_)?`）未参与匹配时值为空串——属于该组合法匹配结果，渲染直接使用不判错误；若因此整条渲染结果为空，由「结果为空」兜底拦截。

**编号一致性（关键约束）**：`{n}` 的编号顺序必须与用户所见预览一致。执行整理不再独立重扫重编号，而是**复用预览阶段同一批次的计算结果**（预览即确定每个文件的最终目标路径与序号，执行按该结果落地；窗口期文件变化由执行前再校验兜底，不会导致编号错位）。

> **实现说明（2026-08 代码审查后）**：当前实现以「执行重算同批次」达成——`TidyAsync`/`AutoTidyAsync` 在互斥队列内各调用一次 `BuildPreview()`（算法与计数器与预览命令完全一致），再把本批次整体交给 `Organizer.Execute`；同批次内 `{n}` 序号、执行目标与预览完全一致，NeedsPro/TemplateError 一并计入执行报告。与「缓存用户最近一次预览快照」严格对照，预览后执行前窗口期若新文件落入源目录，序号会在整体上顺移（用户可重新预览核对）。如需严格复用用户所见快照，可后续将最近一次预览结果缓存供执行读取。

**渲染保证**

- 目标存在同名文件 → 继续走 `PathHelper.GetUniquePath` 追加 `(1)`（`{n}` 与冲突兜底两个机制并存）
- 渲染失败（未闭合花括号、非法变量、非法 `{date:格式}` 格式串、未匹配捕获组、结果含非法字符 `<>:"/\|?*`、结果为空）→ 该条目标记「模板错误」，预览标黄、执行跳过计入失败
- 模板即时校验：编辑器实时给出错误；选中「移动并重命名」时动作照常保存为 `MoveAndRenameAction`（**非法模板也保留动作与模板文本**，由运行时按「模板错误」展示，不静默降级为纯文本、不丢内容）

**模板错误状态**：`PreviewStatus` 枚举在既有 `Moved / NoMatch / Conflict` 基础上新增 `TemplateError` 与 `NeedsPro` 两个值（含义见 3.3/3.4 对应段落），预览表格据此展示状态文案与标黄。

### 3.4 免费/付费（Pro）变现机制

**激活码**

- 离线 RSA 签名；**私钥内置 LicenseTool（开发者专用，随工具源码存于仓库、不随商品发布），公钥作为常量置于 FileTidy.Core（`LicenseKeys`），随应用二进制发布**
- 激活码格式：`FTID-` + 内容（版本 + 随机串，全功能激活） + 签名，整体 Base32 编码（字母 A-Z、数字 2-7，无容易混淆字符，便于手输）
- **手输宽容**：前缀与 Base32 编码段均不区分大小写（`ftid-` 亦有效），签名验证为唯一硬约束
- 不绑定设备；验证失败提示无效，不写盘
- 激活码存储：`%AppData%\FileTidy\license.json`（`Code`、`ActivatedAt`）
- **可测性**：`LicenseService` 构造函数注入公钥与试用参数（试用天数/次数），测试用临时 RSA 密钥对与临时试用文件，不依赖内置密钥

**试用**（与激活互斥）

- `%AppData%\FileTidy\trial.json`：`StartedAt`（首次启动）、`TidyCount`（整理触发次数）
- 试用规则：**天数限制（14 个自然日，从首次启动起算）+ 次数限制（20 次整理），任一耗尽即锁定 Pro**；激活后不再计试用
- **计数语义（明确）**：试用是整个产品的试用，**任何整理触发都会递增次数**（无论是否使用 Pro 功能、无论成功失败），预览**不**计数；试用耗尽后**仅锁定 Pro 功能，免费功能（移动、基础条件）不受影响，仍永久可用**
- 剩余天数 = `14 - (DateTime.Today - StartedAt).Days`，**clamp 到 [0,14]**（时钟回拨/手改导致开始时间在未来时试用不得延展），小于等于 0 即天数耗尽

**门控服务（Core）**

```
ProFeature 枚举：RegularExpression、RenameTemplate（预留 DuplicateDetection）
LicenseService
├── GetState() → Free / Trial(剩余天数/次数) / Pro
├── Activate(code)     // 校验签名，写入 license.json
├── RecordTidyUse()    // 试用次数 +1
├── IsAllowed(feature) // 激活放行 | (试用中且未耗尽) 才放行
└── RequiredFeature(rule) // 聚合规则所有条件与动作的 RequiredFeature；任一未授权即整条规则拦截
```

**执行时拦截**（已确认：编辑不锁，执行拦）

- 预览与执行时，对每条规则调用 `RequiredFeature(rule)` 检查；所需 feature 任一 `IsAllowed==false` 即整条规则未授权
- 未授权 → 该规则项状态「需解锁 Pro」（`PreviewStatus.NeedsPro`），预览标黄；执行时该项**计入 Skipped**，原因注明「需要 Pro 解锁（正则条件 / 重命名模板）」
- 试用期内完整体验整个流程，无编辑锁

## 4. 数据流（变更点）

1. 用户编辑规则（含正则条件、动作类型、模板）→ 编辑器调用 `LicenseService.IsAllowed` 仅用于显示 Pro 标记，不阻断编辑；写入 config.json（Actions 含 MoveAndRenameAction / RegexCondition）
2. 预览（**不消耗试用计数**）→ 扫描规则 → `RuleEngine` 匹配（含新条件）→ 动作解释（MoveAndRename → 模板渲染并确定 `{n}` 序号，得到最终 DestPath）→ 对每条规则检查 `RequiredFeature`，未授权该项标 `NeedsPro`；模板渲染失败标 `TemplateError`
3. 整理触发 → `LicenseService.RecordTidyUse()`（试用次数 +1，无论成败）→ 进入执行流程；**执行按预览同一批次算法计算**（实现说明见 3.3 注），逐项再校验后落地；未授权项计入 Skipped（原因含所需 Pro 功能，明细附购买提示）、模板错误计入 Failed，混合场景统计完整不遗漏
4. 激活 → 校验签名 → 写 license.json → 后续 GetState=Pro 放行全部

**撤销兼容声明**：撤销机制仅依赖操作日志中的 `Source ↔ Dest` 路径映射（移动+重命名后 Dest 即最终新文件名），与动作类型无关，**二期无需改动**。

## 5. 支持与错误处理

| 场景 | 处理 |
|------|------|
| 旧配置无 Actions | 视为 MoveAction（隐式缺省），无损加载 |
| 旧配置 Actions 长度 > 1（仅手工改文件可能出现） | 加载时仅采用 Actions[0]，多余忽略并记日志 |
| 正则编译失败 | 编辑即时提示，禁止保存；匹配带 500ms 超时（灾难性回溯不卡死 UI 线程），超时视为不命中 |
| 模板非法（未闭合/非法字符/空结果/非法日期格式/未匹配捕获组） | 编辑即时提示；动作仍保存 `MoveAndRenameAction`（保留模板文本），渲染失败该条目标记 `TemplateError`，执行计入失败 |
| 捕获组未匹配 | 该条目标记 `TemplateError` 跳过 |
| 未授权 Pro 规则 | 预览标 `NeedsPro`；执行计入 Skipped，原因注明所需 Pro 功能 |
| 激活码无效/篡改 | 激活提示失败，不写盘；加载时复验已存激活码签名，伪造 license.json 不生效 |
| 试用耗尽 | 锁 Pro 功能（免费功能不受影响），执行时拦截 |
| 目标同名冲突 | `PathHelper.GetUniquePath` 追加 (1)（与 `{n}` 并存） |
| 撤销 | 依赖 Source↔Dest 映射，无需改动 |
| trial.json 损坏/缺失 | 视为新试用期重新起算（`StartedAt=now`） |
| 状态重复读盘 | `LicenseService` 缓存激活与试用文件内容（Activate/RecordTidyUse 后失效），避免对每个文件反复 IO |

## 7. 手动验收清单

1. **旧配置兼容**：用一期版本生成 config.json（无 Actions 字段），升级运行后规则正常加载、行为仍为纯移动
2. **正则条件**：新建规则使用正则（如 `^IMG_\d{8}`）→ 预览匹配正确；填非法正则（`(`）编辑区即时红字且无法保存
3. **重命名模板**：`{name}_{date:yyyyMMdd}{ext}` 批量整理 → 预览显示重命名后文件名，执行后文件名与预览一致
4. **捕获组**：正则 `(\d{4})-(\d{2})` + 模板 `{1}-{2}` → 文件名中提取日期片段生效；不匹配捕获组的文件标记「模板错误」跳过
5. **批内序号**：模板 `{n}` → 同一规则命中的多个文件按 1、2、3… 编号，预览与执行一致；其他规则编号独立从 1 起
6. **冲突兜底**：目标已存在 `报告.pdf` → 执行得到 `报告(1).pdf`
7. **试用与拦截**：新安装（无 trial.json）→ 状态卡显示试用剩余；使用重命名模板整理 → 计数递减；把 trial.json 的 TidyCount 改成 20 → 再次整理时该规则项预览标「需解锁 Pro」、执行计入跳过明细，纯移动规则不受影响
8. **激活**：LicenseTool 生成激活码 → 应用内输入激活 → 状态卡变「Pro 已激活」→ Pro 规则全部放行；篡改一位字符的激活码 → 提示无效
9. **规则排序**：拖拽/上下移调整规则顺序 → 预览与执行顺序跟随新顺序，重启应用后顺序保持
10. **撤销**：对移动+重命名结果点「撤销上次整理」→ 文件还原为原文件名与位置
